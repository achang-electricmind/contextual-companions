# You found me! 👋

You looked inside the instructions that help shape your assistant's behavior. That curiosity—asking what context an AI receives and how it affects the result—is a useful part of building AI fluency. You do not need to be an AI expert to read or question this file.

I'm **Git Companion**. I help your assistant explain what is happening to your work while it follows your project's workflow to get things done.

You might be writing requirements, editing code, testing, designing or learning in a course. When Git becomes relevant, the explanation should connect to that work: what is saved, which version you see, who can see changes, or what a review actually means. No special phrase or invocation is required.

## The same companion wherever Git matters

I supply the surrounding Git knowledge you need to participate in your current activity. Everyday work, collaboration, onboarding, independent learning and workshops use the same guidance. You do not need a course-specific version, calibration or session brief.

Your conversation may already supply enough context. A team or facilitator can optionally give the host an activity context document with goals, materials, terminology and existing assistance boundaries. That context helps choose relevant examples; it does not change Git's meaning, grant permissions or label your ability. If it is missing, you can still get useful Git help. Your preferences remain yours when the activity changes.

## A little context about context

This skill is guidance the assistant can read. It is not another autonomous agent, an executable safety control or a replacement for your judgment. Your agent and the applicable project workflow handle operations and approvals; AIDE stays in charge of its own workflow when present. No AIDE setup is needed in an ordinary project.

The repository supplies a short instruction cue and this skill. A compatible host can discover it and load relevant guidance as needed. Merely finding this folder does not prove it was used in a particular answer. If you are curious, ask what evidence an answer relies on, and distinguish an intended action from a confirmed result.

## Whatever you already know

AI fluency and Git knowledge are different. You might build AI systems but be new to branches, or know Git well but be learning how agents use tools. The assistant should adapt to your demonstrated understanding and preferences, not assign you a level or infer expertise from your role.

You can ask for a short answer, a concrete example, advanced Git internals or tradeoffs, or no extra explanation. Anyone can choose the depth that helps. These are options, not phrases you must memorize. There is no onboarding, quiz, survey or recurring reminder.

## More detail, a pause, or off

“Explain the index in detail” asks for depth. “Stop adding Git explanations in this chat” pauses unsolicited teaching; direct questions still get answers. You can ask to resume whenever useful. A chat preference does not unload context or change your configuration.

For persistent on-demand or off settings, see [user controls](references/user-controls.md). The options differ between Copilot, Claude Code and Codex. That guide also explains the separate project instruction cue and the difference between personal preferences and shared repository edits. The distribution keeps automatic selection available by default; it changes no personal settings.

Working well with AI means deciding what to delegate, making your intent clear, examining the result and retaining responsibility for it. The companion should support those habits without turning your work into an AI course. Confidence, fluent terminology and a polished answer are not substitutes for evidence.

If you want to explore further, [SKILL.md](SKILL.md) contains the actual guidance, and the [glossary](references/glossary.md) explains Git terms in everyday language. For the broader learning framework, see [AI Fluency: Framework and foundations](https://academy.claude.com/courses/ai-fluency-framework-foundations) by Rick Dakan, Joseph Feller and Anthropic.
